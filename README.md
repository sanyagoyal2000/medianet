# Media.net Context Studio

A working build of **contextual targeting integrated into Media.net's existing ad server**. Media.net already knows what a page is *about* (SearchSignals, ContextGraph, contextual analysis at scale), and already sells curated deals (SELECT, Deals Desk) with measurement (ELEVATE) and verification partners. Context Studio **extends** these with:

- **F1** — what a page is **for** (purpose) and its **tone**, each backed by a quote from the page, plus confidence and freshness
- **F2** — **who is really requesting** the ad (human, AI app, crawler, buying agent, unknown, suspected invalid); only displayed, human-facing impressions are billed
- **F3** — **planning from a plain-English brief**, in the UI or by a buyer's own AI agent over **MCP**; the output is always a Deals Desk **draft**
- **F4** — a reader-facing **"Why this ad?"** that never mentions the person
- **Phase 2** — **sponsored answers** inside partner AI apps (ShopBuddy pilot); billable only after display is confirmed
- **Phase 3** — licensed content access (planned, explainer only)

Running example: Kohl's "Holiday Gifting 2026". *"20 holiday gifts under $50"* is **Eligible**; *"Holiday toy recall: 40k gifts pulled"* (same topic) is **Excluded: Hard exclusion: Product recalls**. Switch to **Today (topic only)** and the recall would have run.

## Feature map

| ID | Feature | Where |
|---|---|---|
| F1 | Purpose/tone profile with evidence, confidence, freshness | Context Library · Campaign › Targeting · Decision Inspector |
| F2 | Traffic-purpose routing (deterministic, no LLM, < 5 ms) | Traffic Intelligence · Decision Inspector · Overview |
| F3 | Brief → targeting draft; MCP endpoint for buying agents | Campaign › Brief/Targeting · `/api/mcp` |
| F4 | "Why this ad?" (context only) | Ad preview on Targeting · AI App Placements card |
| Phase 2 | Sponsored answers (returned ≠ displayed) | AI App Placements · `/shopbuddy` |
| Phase 3 | Licensed content access | AI App Placements › Licensed content access (Planned) |
| Measurement | Experiment, guardrails, reconciliation, rollout gates | Reports › Experiment monitoring |

## Existing vs new

| Existing Media.net system (simulated in `lib/existing/*`) | What Context Studio adds (new fields, never replaces) |
|---|---|
| ContextGraph topics | purpose, tone, sensitive flags, quoted evidence, confidence, freshness |
| SearchSignals intent | used as the pCTR prior in ranking |
| Deals Desk forecast + deal requests | brief interpreter / MCP agents file **draft** requests only |
| Verification partner (IVT, identity) | request-purpose routing; "Unknown" is never billed as human |
| ELEVATE measurement | purpose & tone pilot with CI, guardrails and gated rollout |

## Architecture

```
Browser (Next.js 15 App Router, Tailwind v4, shadcn/ui, Recharts)
  ├─ app/(studio)/*         Overview, Campaigns, Context Library, Traffic, Decisions, AI App Placements, Reports, Settings
  └─ app/shopbuddy          partner demo chat (own layout)

API routes (runtime = nodejs; agent routes maxDuration = 60)
  ├─ /api/profile            URL → fetch (8 s) → linkedom + Readability → Context Profiler   (NDJSON progress)
  ├─ /api/brief/interpret    Brief Interpreter, Sonnet + tools, max 6 turns                (SSE)
  ├─ /api/eligibility, /api/forecast, /api/explain, /api/campaigns, /api/corrections
  ├─ /api/requests/simulate  build request → Traffic Router (rules only) → store
  ├─ /api/v1/ai-placements   Placement Guard (hard rules → Haiku → code checks → match.ts)  /display /click
  ├─ /api/shopbuddy/chat     ShopBuddy assistant (Sonnet) + placement call with a turn summary only
  └─ /api/mcp                MCP Streamable HTTP (mcp-handler 2.x): 5 planning tools, drafts only

lib/
  ai/          run.ts (timeout, zod validation + retry, agent_runs log, cache fallback), prompts/*.md, models.ts
  context/     profiler, explainer, match.ts (hard rules → soft score), tfidf, extract
  traffic/     router.ts (Web Bot Auth structure + registry, policies as data), simulate.ts
  planning/    briefInterpreter, tools.ts (shared by UI and MCP)
  aiChannels/  placementGuard, placements (offers, display confirmation), shopbuddy
  existing/    SIMULATED ContextGraph, SearchSignals, Deals Desk, verification partner, ELEVATE
  db/          repo.ts → memory.ts (seeded from data/seed, default) | postgres.ts (Drizzle + Neon)
data/seed/*.json (generated by scripts/generate-seed.ts)   data/cache/** (agent outputs for cached mode)
```

Agents: Context Profiler, Explainer, Placement Guard → `claude-haiku-5-5`; Brief Interpreter, ShopBuddy → `claude-sonnet-5-5`; Traffic Router → rules only. Every agent call falls back to the committed cache on no key / timeout / error, and the UI shows a **cached** chip.

## Environment variables (all optional)

| Name | Default | Notes |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Without it, everything runs in cached mode |
| `DEMO_MODE` | `live` if a key exists, else `cached` | Settings can override per browser (cookie) |
| `DATABASE_URL` | — | Neon Postgres; otherwise in-memory (resets on cold start) |
| `MCP_TOKEN` | — | If set, `/api/mcp` requires `Authorization: Bearer <token>` |
| `NEXT_PUBLIC_APP_URL` | request origin | Used in MCP instructions |

## Local setup

```bash
npm i
cp .env.example .env.local   # optionally add ANTHROPIC_API_KEY
npm run dev                  # http://localhost:3000
```

Useful scripts: `npm run check` (prints headline numbers), `npm run seed:generate`, `npm run cache:build` (re-run with a key to replace the hand-authored cache with live outputs), `POST /api/admin/reset` (or Settings › Reset demo data).

### Optional: Neon Postgres

```bash
# add DATABASE_URL to .env.local (Vercel Marketplace › Neon)
DATABASE_URL=... npm run db:push
DATABASE_URL=... npm run db:seed
```

## MCP (buying agents)

- Claude Desktop › Settings › Connectors › Add custom connector › `https://<app>/api/mcp`
- or `claude_desktop_config.json`:

```json
{ "mcpServers": { "media-net-context-studio": {
    "command": "npx", "args": ["-y", "mcp-remote", "https://<app>/api/mcp"] } } }
```

Tools: `find_contexts`, `explain_match`, `forecast_reach`, `create_package` (draft only), `list_campaigns`. Sample prompt: *"Using Media.net Context Studio, find US gift guides and comparisons under $50 for Kohl's holiday campaign, exclude recalls and tragedy, forecast reach, and save a draft package."*

## Demo script (~6 min)

1. **Overview** — "Media.net's workspace with Context Studio switched on."
2. **Campaigns › Holiday Gifting** — Interpret brief → rules fill → gift guide Eligible, toy recall Excluded → toggle **Today (topic only)**: the recall would have run → **Why this ad?**
3. **Context Library** — Add content source: paste a live news URL → profile with real, verbatim evidence.
4. **Inspect request** — a signed crawler → Decision Inspector: content access, no ad billing. Then an unknown → review, never billed as human.
5. **AI App Placements** — shopping question → Kohl's card (billable only after display); recall question → no ad.
6. **Reports** — the pilot is honest (not yet conclusive), guardrails hold, ramp is gated.
7. **Claude Desktop over MCP** — the agent saves a draft → it appears in Campaigns with source **MCP**.
